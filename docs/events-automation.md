# 자동 행사 일정

- `/events`: 날짜별 목록·월간 달력, 지역·온라인·유형·대상 필터. 홈 교계소식 바로 위와 교회 상세에서도 노출한다. 출처 목록은 제목·소개 아래에 두고 공식 교회·기관과 교계뉴스를 구분해 가나다순으로 표시한다.
- 원천 목록은 총 80곳이다. 공식 공지 26곳과 발견용 교계 매체 30곳을 자동 수집 대상으로 연결하고, 24곳은 연결 제한·포스터·기독교 범위 등의 확인이 필요한 탐색 후보로 별도 표시한다. 80곳 전체가 수집 성공했다고 표현하지 않는다. 뉴스는 공식 링크 발견용이며 기사 날짜를 행사 날짜로 쓰지 않는다. 개별 교회 확대보다 광역 행사표, 교육·공연 플랫폼을 우선 연결한다.
- 홈은 화면 너비에 따라 9개·6개·3개로 최대 3줄만 표시한다. 전체 일정은 앞으로 1년을 기본 범위로 날짜순 정렬하고 100개씩 이어서 불러온다. 기간·정기 행사는 회차를 보장할 수 없으므로 달력 날짜별 건수에서 제외하고 별도로 표시한다.
- 두란노 EUC-KR 공지와 공식 `locations(id)` 링크, 광야아트센터 공연 기간, 청어람의 명시된 시작일·주간 횟수, 성남노회 연간 목록의 개별 날짜·시각·교회를 읽는다. 성남노회 파생 후보는 원문 URL의 `#occurrence=` 식별자로 구분하며, 사라진 회차는 재확인 상태로 전환한다. 불명확한 시간 오타·장소 없는 회차는 생성하지 않는다.
- 출처·원문·확인 시각을 공개한다. 주최가 없는 경우 게시처를 주최로 추정하지 않는다. 이미지 전용 공지·불명확한 날짜는 비공개 후보로 남긴다.
- `POST /api/events/sync`는 내부 호출 또는 비밀키로만 접근한다. `EVENTS_SYNC_TOKEN`은 행사 수집에만 사용하며 Sites 비밀 환경변수와 GitHub Actions secret에 동일한 값을 설정한다.
- `.github/workflows/events-sync.yml`은 15분 간격으로 예약된다. 한 번에 3개 출처, 최대 24번의 배치를 처리하고 DB의 실행 잠금·다음 확인 시각으로 중복 실행과 실패 출처의 독점을 막는다. 출처별 최대 10개 후보를 행사 우선으로 처리하며, 50초가 지나면 다음 후보 실행을 중단한다. 최초 대기 자료가 남으면 1분 이후 다음 배치에서 이어가고 정상 재확인은 약 4시간 이후 순회한다.
- 실패 후보도 시도 시각을 기록하여 다음 후보로 진행한다. 공식 원문이 바뀌거나 충돌하면 비공개 확인 상태로 전환하고 재수집으로 해소한다. 마지막 검증 후 24시간이 지난 행사는 목록에서 숨긴다.
- GET은 저장된 데이터만 읽는다. 방문자 수와 무관하게 GitHub에서 수집을 시작한다. Worker scheduled 진입점도 같은 잠금을 사용한다.
- 예약 실행은 정확한 시각을 보장하지 않는다. GitHub 혼잡으로 지연될 수 있고 공개 저장소 활동이 60일 없으면 예약이 비활성화된다. Actions에서 실행 결과를 확인하며, 화면은 12시간 이상 수집 시도가 없으면 지연 상태를 표시한다.
- 각 출처의 최신 목록과 발견된 후보를 순회한다. 확인된 보조 목록·공식 피드도 읽으며, 목록에 실제 연결된 다음 페이지를 최대 10페이지까지 순환한다. 본문 해석 버전이 바뀌면 기존 보류 후보를 한 번 재확인한다. 게시처 전체 과거 글·포스터 OCR·모든 교회 행사까지 망라한다고 표시하지 않는다. 원문 수집 제한을 준수한다.
