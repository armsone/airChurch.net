# 뉴스·행사 출처 일괄 확대

`node scripts/expand-content-sources.mjs --apply`

기존 공식 행사 출처, 뉴스 RSS, 보류 후보 및 `data/content-source-candidates.json`의 조사된 후보를 한 번에 처리한다. 다른 기관은 최대 6곳 동시 처리하고 같은 기관은 순차 처리한다. robots, 요청 간격, 응답 크기 및 시간 제한을 지킨다. 인증·유료 API·접근 제한 우회는 사용하지 않는다.

- `--candidates-only`: 기존 운영 출처의 재검사 없이 신규 후보만 처리.
- `--only=acts,nics`: 지정한 출처 식별자 또는 매체명만 점검.
- `--retry-failed`: 4시간 결과 재사용 중 실패·사실 확인 필요 후보만 다시 검사.
- `--apply`가 없으면 보고서만 작성한다. 있으면 검증을 통과한 신규 출처만 `data/qualified-content-sources.json`에 추가한다. 기존 출처·DB 자료를 덮어쓰지 않는다.
- 진행 상황과 이유는 `outputs/source-expansion/report.json`에 매 출처 완료 시 저장된다. 실패 후 재실행하면 같은 입력의 최근 정상 결과를 재사용한다.

후보 입력은 실제 공식 사이트 조사로 확보한 목록 URL과 `identityEvidence`를 포함한다. 임의 사이트 이름 생성이나 검색 결과만으로 등록하지 않는다. 출처별 상세 경로, 다회차 일정, 복수 장소는 운영 수집기와 동일한 판독 코드를 사용한다. 필요한 경로를 읽지 못하거나 사실이 불명확하면 `adapter_review` 또는 `facts_review`로 남긴다. 일반 티켓 판매처는 기독교 범위가 검증되지 않으면 등록하지 않는다.

`healthy`는 RSS 유효성, `verified`는 기존 행사 출처의 날짜·장소 표본 판독, `qualified`는 신규 출처의 등록 조건 충족을 뜻한다. 과거 행사로 출처를 검증할 수 있지만 종료 행사는 공개하지 않는다. 출처 검증 통과와 운영 서버 수집 성공은 별도 단계다.

프로그램 결과를 확인한 후 사이트의 기존 빌드·배포 절차로 반영한다. 기존 GitHub 행사/뉴스 갱신 작업을 한 번 실행해 서버 DB와 공개 API에서 확인한다. 출처 확대용 2시간 Codex 예약은 사용하지 않는다. RSS는 원문 링크와 기존의 짧은 소개만 제공하며 전문을 재게시하지 않는다.
